# FBV2 BDC 녹화(SHDB) 가이드

FM 안의 화면/OK코드 상수는 "클래식 FBV2 기준 기본값"이다.
릴리스·GUI 설정·화면 변형(Enjoy 화면 등)에 따라 다를 수 있으니
**대상 시스템에서 한 번 녹화해서 상수 블록만 맞추면** 나머지 로직은 그대로 쓴다.

---

## 0. 준비

1. 테스트용 임시전표를 하나 만든다 (FBV1 또는 FV60/FV70 → 저장(파킹)).
   - 되도록 **채권/채무 명세 + G/L 명세가 같이 있는** 전표로 만든다.
     명세 유형에 따라 상세화면 번호(0301/0302/0303)가 달라지는 걸 확인해야 한다.
2. 녹화 전에 GUI 옵션을 운영과 맞춘다.
   - 화면 최대화 상태로 녹화(테이블컨트롤 표시 행 수가 달라짐)
   - `옵션 > 접근성` 켜져 있으면 컨트롤 동작이 달라질 수 있으니 끄고 녹화

---

## 1. 녹화

1. **SHDB** 실행 → `새 녹화(Create)`
2. 입력
   - 녹화명(Recording): `ZFBV2_CHANGE`
   - 트랜잭션 코드: `FBV2`
3. `시작(Start recording)` → FBV2가 실제로 뜬다.
4. 전표를 **평소 하던 대로** 수정한다. 이때 중요한 원칙:
   - **프로그램에서 채울 모든 필드를 손으로 한 번씩 입력**한다.
     값이 안 바뀐 필드는 녹화에 안 남는다 → 화면 필드명을 못 얻는다.
     → BKTXT, XBLNR, 그리고 명세의 SGTXT/ZUONR/ZTERM/ZFBDT/ZBD1T/ZBD1P/
        ZBD2T/ZBD2P/ZBD3T/ZLSCH/ZLSPR/ZBFIX/BVTYP/HBKID/RSTGR 에 더미값 입력
   - **추가 데이터 팝업**(XREF1~3, HZUON)도 반드시 한 번 열어서 값을 넣는다.
     → 이 팝업의 program/dynpro/OK코드를 얻기 위함
   - 명세는 **2건 이상** 수정한다. → 명세 사이를 오갈 때 쓰는
     개요화면 OK코드와 커서 필드(테이블컨트롤 컬럼명)를 얻기 위함
5. 저장(파킹 문서 저장)까지 완료한다.
6. 저장 후 `뒤로(F3)` → SHDB 목록에 녹화가 생긴다.

## 2. 녹화 결과에서 뽑아낼 것

녹화를 선택하고 `표시(Display)` 하면 화면 단위로 목록이 나온다.
필요한 건 딱 네 가지다.

| 뽑을 것 | 녹화에서 보이는 위치 |
|---|---|
| 프로그램명 / 화면번호 | 각 화면 블록의 `Program` / `Dynpro` |
| 화면 필드명 | 블록 안의 `필드명(Field name)` 열 (예: `BSEG-SGTXT`) |
| OK코드 | 각 블록의 `BDC_OKCODE` 값 (예: `=PA`, `=ZK`, `=BU`) |
| 커서 필드 | 각 블록의 `BDC_CURSOR` 값 (예: `RF05V-NEWBS(02)`) |

더 편한 방법: 녹화 화면에서 `프로그램(Program)` 버튼 → 프로그램명 입력 →
`녹화에서 전송(Transfer from recording)` 하면 아래 형태의 ABAP이 생성된다.

```abap
perform bdc_dynpro      using 'SAPMF05V' '0100'.
perform bdc_field       using 'BDC_OKCODE' '/00'.
perform bdc_field       using 'RF05V-BUKRS' '1000'.
...
```

이 텍스트를 그대로 복사해두면 매핑이 쉽다.
(생성한 프로그램은 참고용이고, 실제로는 FM 쪽 상수만 바꾸면 된다)

## 3. FM 상수 블록에 옮기기

`z_fi_parked_doc_change_bdc.abap` 상단의 상수 블록과 1:1로 대응된다.

| 상수 | 녹화에서 확인할 값 |
|---|---|
| `lc_prog_init` / `lc_dynp_init` | 첫 번째 화면(회사코드/전표번호/회계연도 입력) |
| `lc_prog_ovw` / `lc_dynp_ovw`   | 두 번째 화면(헤더 + 명세 목록이 같이 보이는 개요화면) |
| `lc_prog_item` / `lc_dynp_item` | 명세를 더블클릭했을 때 나온 상세화면 |
| `lc_prog_more` / `lc_dynp_more` | 추가 데이터 팝업 |
| `lc_fld_ovwpos` | 개요화면에서 명세를 고를 때 찍힌 `BDC_CURSOR` 의 **괄호 앞부분**<br>예: `RF05V-NEWBS(02)` → `RF05V-NEWBS` |
| `lc_ok_enter` | 초기화면에서 Enter 쳤을 때의 OK코드 (`/00` 또는 `=ENTR`) |
| `lc_ok_itemdet` | 개요화면 → 명세 상세로 갈 때의 OK코드 |
| `lc_ok_more` | 상세화면 → 추가 데이터 팝업 OK코드 |
| `lc_ok_back` | 상세화면 → 개요화면 복귀 OK코드 |
| `lc_ok_save` | 저장 OK코드 |

그리고 **필드가 어느 화면에 있었는지**에 따라
`lt_item_map` 의 `block` 값을 맞춘다.

- `block = 1` : 명세 상세화면에 있던 필드
- `block = 2` : 추가 데이터 팝업에 있던 필드

화면 필드명이 다르면(`BSEG-XREF1` 이 아니라 다른 이름이면) `dynfld` 도 같이 고친다.

## 4. SHDB 없이 확인하는 방법 (보조)

FBV2를 직접 띄워놓고

- 필드 위에서 **F1 → 기술정보(Technical Information)**
  → `화면 필드(Screen field)`, `프로그램(Program)`, `화면번호(Screen number)` 확인
- 메뉴 기능의 OK코드는 **`시스템 > 상태(Status)`** 또는
  해당 GUI 상태를 SE41에서 열어 기능코드 확인

급하게 한두 개만 확인할 때 유용하다. 전체 흐름은 SHDB가 정확하다.

## 5. 테스트 순서 (권장)

1. `IV_MODE = 'A'` (전체 화면 표시)로 호출 → 화면이 하나씩 넘어가는 걸 눈으로 확인
   - 화면이 멈추는 지점이 있으면 그 화면 블록이 빠졌거나 OK코드가 틀린 것
2. `IV_MODE = 'E'` (오류 시에만 화면 표시)로 다시 실행
3. 정상 동작 확인 후 운영은 `IV_MODE = 'N'` (무화면)

디버깅 팁
- `ET_MESSAGE`(BDCMSGCOLL)에 실제 SAP 메시지가 담긴다. `MSGID/MSGNR/MSGV1~4` 로
  SE91에서 원문 확인 가능.
- "화면에 필드가 없습니다" 류 오류 → 그 명세 유형에 없는 필드를 보냈다는 뜻.
  (예: G/L 명세에 ZTERM 전송)
- 화면이 안 넘어가고 멈춤 → OK코드 또는 화면번호 불일치.
- 값이 반영 안 됨 → 날짜/소수점 포맷 문제. FM은 `WRITE ... TO` 로
  사용자 포맷 변환을 하지만, 배치 사용자(BDC 실행 계정)의 SU3 기본값
  (날짜형식/소수점표기)이 다르면 결과가 달라진다. **RAP에서 호출하는 계정 기준**으로 확인.

## 6. 자주 걸리는 함정

| 증상 | 원인/대응 |
|---|---|
| 명세 3번부터 안 잡힘 | 개요화면 테이블컨트롤에 안 보이는 행. `POSID`(화면 행번호)를 직접 넘기거나 `P+` 스크롤 블록을 FM에 추가 |
| 어떤 사용자에서만 실패 | GUI 해상도/표시행수 차이. `ctu_params-defsize = 'X'` 로 이미 고정해 두었지만, 녹화도 같은 조건에서 |
| 세금코드/차이 경고 팝업이 뜸 | 녹화 때 안 뜬 조건부 팝업. 해당 케이스를 재녹화해서 팝업 블록을 조건부로 추가 |
| FBV2가 Enjoy 화면(SAPLFDCB)으로 뜸 | 회사코드별 편집옵션/파킹 방식 차이. 그 경우 화면 구성이 완전히 다르므로 그 화면 기준으로 다시 녹화해서 상수/매핑을 교체 |
| RAP에서 호출 시 이상 동작 | `CALL TRANSACTION` 이 자체 COMMIT 을 한다. SAVE 단계에서만 호출할 것 |
