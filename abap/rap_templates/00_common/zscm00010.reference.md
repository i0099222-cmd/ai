# ZSCM00010 (히스토리 include 구조) 전제

본 템플릿은 `ZSCM00010` 이 **RAP 표준형 5필드**로 구성되어 있다고 전제하고 작성되었다.

| 필드명                  | 데이터 엘리먼트                   | 용도                          | RAP 역할                    |
|------------------------|----------------------------------|-------------------------------|----------------------------|
| CREATED_BY             | `abp_creation_user`              | 생성자                        | createdBy                  |
| CREATED_AT             | `abp_creation_tmstmp`            | 생성일시 (UTC timestampl)     | createdAt                  |
| LAST_CHANGED_BY        | `abp_lastchange_user`            | 최종변경자                    | lastChangedBy              |
| LAST_CHANGED_AT        | `abp_lastchange_tmstmp`          | 최종변경일시 (UTC timestampl) | **total ETag**             |
| LOCAL_LAST_CHANGED_AT  | `abp_locinst_lastchange_tmstmp`  | 인스턴스 최종변경일시         | **ETag (낙관적 잠금)**     |

## 실제 필드명이 다를 경우

CDS 뷰의 element 명(`CreatedBy`, `CreatedAt`, `LastChangedBy`, `LastChangedAt`, `LocalLastChangedAt`)은
템플릿 전체에서 그대로 유지하고, 아래 **두 곳만** 수정하면 된다.

1. `ZDQ_I_*` interface 뷰의 select list — `OrderHeader.created_by as CreatedBy` 좌변
2. behavior definition 의 `mapping for <table>` 블록 — 우변 DB 필드명

## managed RAP 의 자동 채번

`@Semantics.user.createdBy` / `@Semantics.systemDateTime.createdAt` / `@Semantics.user.lastChangedBy` /
`@Semantics.systemDateTime.lastChangedAt` / `@Semantics.systemDateTime.localInstanceLastChangedAt`
애노테이션이 붙어 있으면 managed 시나리오(Case 2, 3)에서 프레임워크가 자동으로 채운다.
Case 5(managed with unmanaged save), Case 7(unmanaged)은 자동 채번이 없으므로 saver 에서 직접 채운다.
